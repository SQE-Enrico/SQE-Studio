# Web Research Experiments — Compatibility Guide (v0.17.0)

**The supported starting point is now `/`: Project → Setup → Run → Results → Support ZIP.**

This legacy guide is retained for users of v0.16.0 and bookmarks to its individual pages. The new unified workspace combines normal project selection, optional engine installation, experiment and test execution, debugging and ZIP downloads in one interface. Use [Unified Web Workflow](unified-web-workflow.md) for setup, security, environment isolation and the current recommended workflow.

The old `/experiments.html` continues to expose direct multi-engine workflows and `/control.html` continues to expose specialized diagnostics. They are optional advanced interfaces, not prerequisites for a regular experiment. Existing project data, diagnostics records and test cases have not been discarded.

Every finished or failed experiment supplies a self-contained, privacy-reviewable ZIP containing manifest, checksums, logs and available artifacts. Normal jobs and diagnostics have equivalent support downloads. A passing ZIP integrity check is not proof of scientific accuracy. Palace numerical quality, SQDMetal integration, Julia nonlinear solve validation and fabrication checks are separate tasks.
