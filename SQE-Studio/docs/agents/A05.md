# A05 — JosephsonCircuits.jl bridge (implementation interface)

**Status: adapter implemented; native Julia execution NOT VERIFIED in the A05 build environment. This document is not scientific qualification.** This is an agent-owned interface proposal for A01/A06, not a frozen-contract change. No automatic EM-to-netlist mapping is supported.

## Trusted, immutable input

The existing registry invokes `josephson_adapter.run(study, project, output_dir)` with an immutable job snapshot. The study must have `engine: "josephson_circuits"` and `kind: "rf_linear"` or `"rf_harmonic_balance"`. **It does not accept an inline Julia program, uploaded netlist filename/path, or arbitrary code.** It reads only `project.schematic` from that revision. Its `inputs.schematic_sha256` must equal SHA-256 of the canonical JSON serialization (`json.dumps(schematic, sort_keys=True, separators=(',', ':'), allow_nan=False)` UTF-8). The snapshot-wide `revision_id` and `project_digest` are bound by the frozen shared worker's `RESULT_MANIFEST.json`, not provided inside this adapter.

For a linear study:

```json
{
  "id": "RF1", "engine": "josephson_circuits", "kind": "rf_linear",
  "inputs": {
    "schematic_sha256": "<64 lowercase hex digits of exactly the saved schematic>",
    "frequencies_hz": [4500000000.0, 4750000000.0, 5000000000.0]
  }
}
```

Example `project.schematic` for that study (digest must be calculated from the actual revision):

```json
{
  "nodes": ["0", "n1", "n2"],
  "elements": [
    {"id": "Ccouple", "kind": "C", "nodes": ["n1", "n2"], "value": 1e-13, "unit": "F"},
    {"id": "Lres", "kind": "L", "nodes": ["n2", "0"], "value": 1e-9, "unit": "H"}
  ],
  "ports": [
    {"number": 1, "node": "n1", "reference_impedance_ohm": 50.0}
  ]
}
```

For a supported experimental **single-tone, current-driven Josephson harmonic-balance** study, use `kind: "rf_harmonic_balance"`, include at least one `Lj` element in the saved schematic and add `inputs.pump`:

```json
{
  "frequency_hz": 4750000000.0,
  "port": 1,
  "current_a": 1e-9,
  "pump_harmonics": 2,
  "modulation_harmonics": 1
}
```

This example is **not** a verified native operating point, calculation or physically qualified design. No DC bias, flux-pump coupling, multi-pump/multi-tone, arbitrary input-source waveforms, idler S extraction, multicomponent frequency dependence, or custom Julia functions are accepted. Static `R`, `L`, `C`, `Lj` map respectively to the native resistor, inductor, capacitor, and Josephson inductance (all positive SI). A junction is specified by its Josephson inductance `Lj` in henries, **not** by silently converting a critical current; deriving `Lj` is upstream reviewed work.

## Native reference-plane and port convention

- The only ground is named literal `"0"`; element nodes reference declared identifiers. Every declared node must participate and connect to ground via saved **real** elements, not only via the generated port shunt. Port nodes must be distinct and non-ground, and must be single-ended (node-to-`0`). Other circuit terminal arrangements must be mapped and reviewed upstream.
- Port numbers are precisely `1..N` with no duplicates (max four); their order is **ascending port number**, not UI insertion order. For each port `i`, the worker emits a native `("Pi", node, "0", i)` plus a dedicated matching `("Rporti", node, "0", z0_ohm)`. A second explicit resistor directly across such a port is rejected, since the native port-shunt impedance identification would be ambiguous. `z0` is finite, real, positive 1–10,000 ohms. No auto-50-ohm fallback.
- Native `portnumbers` and count of `portimpedanceindices` are checked against the requested ports, otherwise the run is rejected. The native library computes `S`: no SQE S/Y/Z conversion, no custom normalization equation, and no internal solver. The normalization is JosephsonCircuits' native Kurokawa-style **power-wave** convention (described in its API as photon-flux-amplitude waves) with real positive port-reference impedances. Complex S is a dimensionless outgoing/incoming wave amplitude **ratio**.
- The unmodified numerical result is written in `josephson_native_sparameters.tsv`: header `frequency_hz, output_port, input_port, real, imag` (tab-separated), one row per `(frequency, output port, input port)` in that exact nested order. The requested signal frequencies in Hz are internally passed as angular frequencies `2π f` rad/s. Native `S((0,), out, (0,), in, k)` is the signal-to-signal mode only. **For pumped circuits idler S is not extracted** and this result is not a full multimode matrix or a pumped amplifier qualification.
- A01 can consume the explicit sidecar `josephson_ports.json` (`sqe.josephson-port-contract.v1`), digest of the schematic, reference impedance per port, port polarity, order, source-native details and limitations. A06 can collect the fixed named files under the existing worker ABI and attach its frozen revision/provenance manifest. Sidecars do not imply A01/A06 agreed to a frozen schema.

## Native execution and laptop bounds

The Python adapter encodes a fixed, checked TSV request and materializes the constant `josephson_fixed_worker.jl` source embedded in the adapter. The subprocess invocation is an argv sequence: resolved `julia` executable from trusted worker PATH, `--startup-file=no`, `--history-file=no`, `--threads=1`, fixed script and fixed request/output paths. `shell=False`; no `eval`, `include`, or browser-supplied Julia expressions. `using JosephsonCircuits` must succeed **in the installed Julia environment**. There is no package auto-download or silent fallback. Julia `Base.pkgversion(JosephsonCircuits)` supplies the native version; failure blocks output. Target: Julia 1.10+ / verified JosephsonCircuits installed by the operator, version not qualified by A05.

Circuit limits are 2–24 declared nodes (including ground), 1–48 real elements, 1–4 ports, 1–64 explicit strictly ascending signal frequencies in 1 kHz–1 THz, and maximum one single-tone pump at 1 MHz–100 GHz, 1 fA–100 μA, pump harmonics 1–4 and modulation harmonics 1–2. Real SI component bounds are enforced by type. Native execution has 140-second adapter timeout under the parent worker's 180-second cap, Julia threads and `nbatches` equal one, BLAS threads capped at one. **Global run concurrency** is enforced by the existing shared jobs layer; A05 cannot edit it. Check by A06 at integration; do not run the adapter standalone concurrently from multiple processes.

Linear RF uses JosephsonCircuits' `hblinsolve`; nonlinear RF uses native `hbsolve`, with one `(mode=(1,),port=i,current=A)` source, `dc=false`, `threewavemixing=false`, `fourwavemixing=true`, `iterations=80`, `ftol=1e-8`, no custom initial guess, no source scripting. The native solver's success/error and stdout/stderr are recorded. Native iteration-by-iteration convergence history/residual is **not available from this extraction and must not be inferred**. `hbsolve` returning without throwing is recorded only as `hbsolve_returned_no_iteration_log`, not certified convergence. Outputs remain `review_required` and `HOLD`.

The successful run returns `engine_version`, `kind: josephson.sparameters`, and these named files for worker hashing:

`josephson_request.tsv`, `josephson_fixed_worker.jl`, `josephson_native_sparameters.tsv`, `josephson_native_metadata.tsv`, `josephson_native_stdout.log`, `josephson_native_stderr.log`, `josephson_ports.json`.

Input/data/artifact files are never overwritten on an existing Josephson job output path. An invalid saved circuit, unsupported pump, missing Julia binary/package, timeout, Julia error, malformed native port mapping, nonfinite/missing S values, or package version ambiguity results in `EngineBlocked`/`EngineFailure` **with no admitted native S manifest**. If a subprocess fails, stdout/stderr and the fixed request remain evidence in the failed job directory. The outer immutable snapshot worker writes `FAILURE.json`. Neither a GUI-only schematic nor an arbitrary uploaded netlist is certified as a validated physical circuit or junction fabrication drawing.
