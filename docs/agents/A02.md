# A02 native Quantum Metal adapter: implementation contract

**Status:** A02-owned implementation delta; **not** an integrated or fabrication-qualified release.

The unchanged foundation defines `project['layout']` as the canonical saved,
revision-bound declarative recipe. `build_qdesign(layout)` consumes that exact
mapping without editing it, constructs a native `qiskit_metal.designs.DesignPlanar`
and returns a frozen `QDesignBuild` descriptor containing the actual in-process
`design`, canonical SHA-256 of the layout JSON, component names, created native
pin identities, explicit route/net labels and endpoints, QGeometry layers, and
junction cell IDs/layers. This is the **A03 in-process handoff**; it is not a
serialized QDesign, derived netlist, EM result, or authenticated revision object.
The caller (A06 worker) binds immutable project and revision digests.

## Allowlist and exact recipe

Reviewed names and *literal* import paths are defined in the A02 adapter:
`TransmonPocket`, `TransmonCross`, `ResonatorLumped`, `ReadoutResFC`,
`LaunchpadWirebond`, `OpenToGround`, `ShortToGround`, `RouteStraight`,
`RouteMeander`, `RouteAnchors`, `RoutePathfinder`. Native class imports occur
only through this static allowlist; no code, Python expression, arbitrary module
path, or user-defined QComponent is interpreted. In the layout:

- `chip`: `width_mm`, `height_mm`, `thickness_um` (bounded finite numerics).
- Physical components: `kind`, `name`, `x_mm`, `y_mm`, and optionally
  `orientation_deg`, `layer`, `options` (reviewed dimension names suffixed `_um`),
  `connection_pads` (only reviewed TransmonPocket/TransmonCross connector keys),
  `junction_cell`, `n_turns` (ResonatorLumped), or `subtract_layer` (required for
  ReadoutResFC).
- Routes are **also entries in** `layout.components` and require `kind`, `name`,
  `net`, `start: {component, pin}`, `end: {component, pin}`. Supported optional
  parameters: `layer`, `trace_width_um`, `fillet_um`; `RouteMeander` additionally
  `total_length_mm`, `meander: {spacing_um, asymmetry_um?}`; `RouteAnchors` and
  `RoutePathfinder` accept ordered `anchors: [{x_mm, y_mm}, ...]`; pathfinder
  supports `constraints: {avoid_collision: true}`, `step_size_um`.
- GDS drafts additionally require `layout.gds` containing
  `layer_map: {main: [integer_layer, ...]}`, and
  `negative_layers: [integer_layer, ...]`. All QComponents and any explicitly
  subtracted geometry layers must be in this list. No default mask map is
  pretended to be an approved PDK.

Example *GDS recipe with no Josephson junctions* (a draft, not foundry-ready):

```json
{
  "engine": "quantum_metal",
  "chip": {"width_mm": 8, "height_mm": 8, "thickness_um": 500},
  "components": [
    {"kind": "LaunchpadWirebond", "name": "P1", "x_mm": -1, "y_mm": 0},
    {"kind": "LaunchpadWirebond", "name": "P2", "x_mm": 1, "y_mm": 0, "orientation_deg": 180},
    {"kind": "RouteStraight", "name": "R1", "net": "Feedline",
      "start": {"component": "P1", "pin": "tie"},
      "end": {"component": "P2", "pin": "tie"}}
  ],
  "gds": {"layer_map": {"main": [1]}, "negative_layers": []}
}
```

The builder sorts terminals by name, then routes by name; rejects duplicate
component IDs and net labels, reused terminal pins, nonexistent native pins,
unknown components/options, cross-layer routes and missing QGeometry. Native
route endpoint `net_id` values must be nonzero and equal. It neither creates
implicit pin links nor accepts arbitrary constraint expressions. The native
QGeometry table, not SQE-generated shapes, is the geometry authority.

## GDSII and HOLD gate

`run(study, project, output_dir)` permits only `gds_draft`. The **only GDS
writer** is `QGDSRenderer.export_to_gds`. Per-layer native `negative_mask`
configuration is derived from the explicit recipe; native subtraction is left
inside Quantum Metal QGeometry/rendering; `fabricate=False` and a mandatory
`gds_hold.json` explicitly retain `HOLD`. After export, a bounded read-only GDSII record scan
structural inspection checks that all native QGeometry layers appear, no GDS
layer is outside the declared map, and any required cell names are present.
The GDS is deleted on renderer/readback failure. SQE never creates fallback GDS.

**Josephson junction exports are always BLOCKED:** junction-bearing components
require explicit named cells, and, even when declared, `run` refuses export
until authenticated, content-hashed GDS junction library staging, cell/layer
verification and process provenance are specified in a reviewed shared
contract. No default/demo/fake junction cell is a safe replacement. Native
`build_qdesign` still supports the explicit transmon geometry and QGeometry
junction table for A03 when Quantum Metal is installed.

## Typed migration request for A09, not made here

Suggested `sqe.project.v2` layout extension (A01/A06/A08/A09 review required):
`gds.junction_asset: {artifact_id: UUID, sha256: hex64,
source_revision_id: UUID, validated_cell_ids: [identifier],
cell_layers: [integer], units: unit, evidence_id: UUID}`. A trusted worker
must resolve the asset to an immutable, run-scoped, read-only file path, verify
its digest/cell names and junction geometry layer mapping before passing it to
`QGDSRenderer.options.path_filename`. A09 should also freeze and version the
recipe key schemas above, explicit routed net graph for branched connections,
constraints and registered physical stack maps. The present `sqe.project.v1`
validator permits these additive `layout` members but does not enforce their
typed semantics at commit time; A02 currently validates again at native run.

## Interoperability limits

No independent conductor/ground polarity validation, fabrication mask signoff,
DRC, LVS, PDK layer qualification, cross-chip interconnects, backend solver,
physics approximation, or verified EM-to-qubit model mapping is provided.
Native Python package and external GDS viewers must be independently installed
and tested on target Windows 11. Provenance for a saved revision and generated
files remains at the worker's frozen ABI boundary; in-memory QDesign itself is
not a revision-authentication mechanism.
