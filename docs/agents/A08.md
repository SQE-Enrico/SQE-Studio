# A08 service security / Windows 11 operations

Scope: `src/sqe_studio/server.py`, `src/sqe_studio/store.py`, `scripts/`, `requirements/`, `tests/security/` and this owned document/report. The source foundation/frozen contracts and other agent components remain unchanged.

## Local service and credential lifecycle

- The service always binds `127.0.0.1`, not `0.0.0.0`. The accepted HTTP Host values are `127.0.0.1:<port>` and `localhost:<port>` only. Duplicate Host, hostile Origin, cross-site fetch metadata, malformed JSON framing, nonfinite/duplicate JSON fields and large requests are rejected. JSON is capped at 256 KiB, reads time out, and request logs never print URLs, query values, cookies, tokens or bodies.
- `GET /api/status` is unauthenticated local health. Other project APIs require a session with a token-hashed database record. All authenticated POST actions require the session's `X-CSRF-Token`. Cookies are `HttpOnly`, `SameSite=Strict`, restricted to `/`, and expire at eight hours. Insecure localhost HTTP cookies are **not** suitable for network access; do not proxy this service or use it on a shared network.
- On first run a 256-bit-class random setup token is written in a private, non-symlinked data folder. Only the local console presents it. The token is deleted after successful first account creation; a stale token is deleted if an account already exists.
- New passwords require 12–1024 characters, are PBKDF2-HMAC-SHA256 hashed with a random salt and 600,000 iterations. Old 250,000-iteration hash records are checked and upgraded on successful login. An authenticated `POST /api/password` accepts exactly `current_password` and `new_password`, checks session CSRF and old password, rotates the salt and revokes **all** sessions; log in again. This endpoint is API-only until A07 provides UI controls. A per-process 12-failure/5-minute login brake limits local guessing; it is not distributed rate limiting.
- SQLite uses busy timeouts, WAL and `BEGIN IMMEDIATE` for first account, immutable head revision CAS and password rotation. Each project and run lookup remains restricted to its owning account. Run results/downloads check run UUID, owned revision ID, source digest, study and engine, and disallow symlink-redirected result paths. Jobs and scientific outputs remain owned by A06/A02–A05.

## Offline Windows 11 install

1. Use a Windows 11 x64 device with Python **3.11** and an explicitly reviewed build wheelhouse; see `requirements/README.md` and `requirements/build-win11.txt`. Do not treat the Linux test evidence as a Windows pass.
2. From the product root run `powershell -NoProfile -File scripts/Build-Windows11Wheel.ps1 -Wheelhouse C:\path\to\reviewed-wheelhouse`. The script builds **core only**, with fixed `SOURCE_DATE_EPOCH`, no network, and emits a `.whl.sha256` sidecar. Inspect/approve the wheel and its hash. This sidecar detects alteration but is **not** a signature or independently trusted provenance record.
3. Run `powershell -NoProfile -File scripts/Install-Windows11.ps1 -WheelPath release\sqe_studio_product_foundation-0.1.0-py3-none-any.whl`. The installer refuses existing directories and unverified wheels; it uses `--no-index --no-deps`, validates the installed HTML/CSS/JS byte hashes against the wheel, and tests service startup as an independent child process. It never auto-installs scientific engines.
4. Launch the printed command using the installed `venv\Scripts\python.exe` and a **private, separate data directory**. Keep the first-run console token private. Check `http://127.0.0.1:8000/api/status` and `http://127.0.0.1:8000/` locally. Engine availability indicators are not solver convergence evidence or foundry qualification.
5. To update, stop the service, back up the **quiesced** database (including WAL/SHM) plus native artifacts, verify backup hashes, build a new isolated version, and have A09 approve any versioned schema migration before re-pointing to data. Never silently re-import legacy workspaces or edit saved revision snapshots.
